## What this proves, and what it does not

Proves: a reviewer with this commit, `nasm`, `python3`, `qemu-system-x86_64`,
`gdb` and one 9.3 MB vendor blob can re-run each of the five rows above without
this box's working files, and the references BM602 and BM653 pin are the bytes
rung 9
emits there (the three `_leg0` dumps hashed to the pinned sha256s — see the
BM903 record).

Does not prove:
* **BM651 twice.** Its own closure ran the gate ×2; pristine ran it once (the
  landed GATE651 line above is that single run). Not re-run a second time here
  because nothing about the prerequisite chain changes between passes, and the
  row's autologin-sensitive legs cost boots.
* **The full BM802 sensitivity map** — 319 boots, ~165 min, planned `--dry`
  identically and deliberately not re-run.
* **Anything about hardware.** All of it is TCG; Rung 8's silicon row (BM801)
  is unchanged and still unstarted.
* **That `git status` is the way to see the missing inputs.** It is not, for one
  of them: `rung7/TinyCore-current.iso` is ignored by `.gitignore:68 *.iso`, so
  the cleanest checkout on the box lacks a 28 MB file that no `git status`
  invocation will ever mention. `bm001_landing_plan.sh` reports it; TASK_BM001
  is the decision about it.
